## PASOS PARA CONTINUAR EN LA OTRA PC

1. Extraer el .7z con 7-Zip (contraseña del backup)

2. Abrir la carpeta tropigo-ai (o TropiGO-AI):
   cd tropigo-ai

3. Copiar el archivo .env del backup a la raíz del proyecto
   (o si clonaste desde GitHub, pegar el .env manualmente)

4. Instalar y correr:
   npm install
   npx prisma generate
   npm run dev

5. La BD ya está en Supabase — NO instalar PostgreSQL.

## VARIABLES DE ENTORNO (.env)

   Las variables están en el .env del backup. Las principales:

   - DATABASE_URL / DIRECT_URL — Supabase pooler
   - NEXT_PUBLIC_SUPABASE_URL — URL pública de Supabase
   - NEXT_PUBLIC_SUPABASE_ANON_KEY — Clave pública
   - SUPABASE_SERVICE_ROLE_KEY — Clave de servicio
   - GROQ_API_KEY — Groq IA
   - GEMINI_API_KEY — Gemini IA
   - OPENROUTER_API_KEY — OpenRouter IA
   - GEMINI_BACKUP_KEY — Gemini respaldo
   - ENCRYPTION_KEY — Cifrado AES-256
   - APP_URL — URL pública (cambiar a https://tropigo-ai.vercel.app en prod)
   - ADMIN_EMAIL / ADMIN_PASSWORD — Login admin
   - WHATSAPP_PROVIDER — META_CLOUD_API (producción) o BAILEYS_QR (pruebas)

## CÓMO CONTINUAR CON LAS MEJORAS

   1. Abrir el proyecto en tu IDE (VS Code, OpenCode, etc.)
   2. Leer docs/MEJORAS-OPENCODE.md — tiene las instrucciones validadas
   3. Copiar el prompt de la Sección 6 de esa guía y pegarlo en tu agente IA
   4. Implementar en orden: A1 → A2 → A3 → A4 → A5 → A6 → A7
   5. Después de cada mejora: npx tsc --noEmit && npm run build
   6. NUNCA ejecutar prisma migrate reset ni npm run db:seed

## SI LAS API KEYS SE AGOTAN

   Los 3 proveedores tienen capa gratuita generosa. Si se agotan:
   1. Crear nueva cuenta con otro email
   2. Generar nueva API Key
   3. Ir a Dashboard → IA → pegar la nueva clave
   4. Click en "Probar Conexión"
   5. El sistema rota automáticamente: Gemini → Groq → OpenRouter → Simulador
